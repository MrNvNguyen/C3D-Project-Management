## Implemented (one lever)

Project + global task lists share HSPL Excel contract in `public/static/app.js`:

| Behavior | Implementation |
|---|---|
| Empty last row (current page slice) | `#projTasksTbody` + `#tasksTable` append `.task-grid-row.is-new` after paginated rows |
| Enter / blur commit | `taskGridCommitRow` → POST `/api/tasks` or PUT `/api/tasks/:id` via `buildTaskPayloadFromGrid` |
| Skip unchanged PUT | `_taskGridPayloadUnchanged` |
| Tab / Shift+Tab | `_taskGridTabNavigate`; combobox cells focus `[data-cb-trigger]` |
| Escape | `taskGridCancelCell` restores `data-task-grid-orig`, no API |
| Paste multi-line titles | `taskGridTitlePaste` sequential `await taskGridCommitRow` (not `Promise.all`) |
| Main create path | `btnNewTask` + project «Tạo task» → `taskGridFocusNewRow` (no `openTaskModal` on primary create) |
| Modal SSOT payload | `taskForm` submit uses same `buildTaskPayloadFromGrid` as grid |
| Member RBAC UI | `_taskGridPermissions` mirrors modal: limited edit → status/progress only; new row assignee locked for members |
| Visual | Status ring (Wave B / legal ring tokens), due pill, priority select + badges |

**Not touched:** `src/index.tsx`, `src/finance.ts`, migrations, D/D2 payment/Cost A, executive-dashboard, app.v2.js, task DnD.

## Payload parity vs `saveTask` / task modal

`buildTaskPayloadFromGrid` fields align with former `taskForm` `data` object:

`project_id`, `category_id`, `title`, `description`, `discipline_code`, `phase`, `priority`, `status`, `assigned_to`, `start_date`, `due_date`, `estimated_hours`, `progress`, `work_notes`, `cde_report`, `hstk_date`, `task_type`, `model_filename`.

Grid create defaults: `phase=basic_design`, `priority=medium`, `status=todo`, `task_type=model`, `progress=0`, `start_date=today()`, `estimated_hours=0`, member `assigned_to=self`.
