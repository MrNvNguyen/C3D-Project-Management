## Mục đích

Sau deploy code Wave A, D1 production/local có thể còn `payment_requests` **pending** / **rejected** (hoặc **amount = 0**) vẫn giữ `revenue_id` do gate cũ (`shouldSync = amount > 0` mọi status). Resync áp gate mới: xóa revenue + NULL `revenue_id` cho phiếu không được book; book lại **processing** / **partial** / **paid** với `amount > 0`.

## Ai được chạy

- Role: **`system_admin`** (route `adminOnly`).
- Không chạy qua member / project_admin nếu chưa có quyền system.

## Endpoint

| Scope | Method | Path |
|---|---|---|
| Một dự án | `POST` | `/api/legal/:projectId/resync-revenues` |
| Toàn DB | `POST` | `/api/legal/resync-revenues-all` |

**Auth:** `Authorization: Bearer <token>`.

**Sau Wave A (bắt buộc):** SELECT phải gồm mọi phiếu có thể còn link:

```sql
status IN ('processing','partial','paid','pending','rejected')
OR revenue_id IS NOT NULL
```

Payload gọi `syncPaymentToRevenue` phải có **`request_date`** (từ cột `payment_requests.request_date`).

## Pre-flight (trước resync)

1. Ghi **git SHA** deploy / working tree Wave A.
2. `GET /api/finance/revenue-audit` — lưu JSON (broken_links, orphan_revenues, formula_mismatches).
3. Snapshot thủ công (optional, Q2): đếm phiếu vi phạm gate mới:

```sql
SELECT id, project_id, status, amount, revenue_id
FROM payment_requests
WHERE revenue_id IS NOT NULL
  AND (status IN ('pending','rejected') OR amount = 0);
```

Kỳ vọng sau resync: **0** dòng.

## Thực hiện

1. **Staging / local D1 trước** (Q2 bắt buộc trước production).
2. Gọi `POST /api/legal/resync-revenues-all` (hoặc theo project nếu pilot một dự án).
3. Response: `synced`, `total`, `errors[]` — nếu `errors` không rỗng, dừng và report-up (attempt cap Wave A).

## Post-flight (pass criteria)

1. `GET /api/finance/revenue-audit` — không tăng broken_links / orphans; formula_mismatches chỉ còn case ngoài phạm vi gate (nếu có, ghi NOT_MEASURED).
2. Gate mới:

```sql
SELECT COUNT(*) AS bad_links
FROM payment_requests
WHERE revenue_id IS NOT NULL
  AND (status IN ('pending','rejected') OR amount = 0);
```

**Pass:** `bad_links = 0`.

3. Q2 Layer B (một phiếu trên HSPL): fixture **1_100_000**, VAT **10%**, fee **30%** → booked **700_000** khi status **processing** (kể cả `paid_amount = 0`); **pending** không còn dòng `project_revenues` tương ứng.

## Rollback / rủi ro

- Wave A **không** migration — rollback = revert deploy + resync lại trên bản cũ (sẽ book lại pending; chỉ làm nếu PO quyết định).
- Không sửa `computeBookedRevenue`, dashboard/analytics SQL trong wave này — KPI có thể lệch tạm nếu resync chưa chạy trên D1 đo.

## Evidence (QA ghi)

- SHA, môi trường (local wrangler / staging URL).
- Pre/post `revenue-audit` JSON path hoặc hash.
- Một phiếu: status transitions + số booked trên API đã auth (không chỉ vitest).
