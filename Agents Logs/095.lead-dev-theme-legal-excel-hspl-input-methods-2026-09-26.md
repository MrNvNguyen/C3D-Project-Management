## Root cause

Checklist / payment inline handlers embedded `JSON.stringify(item)` (and `&quot;` escapes) in HTML `onclick` / `onchange` / `onblur`. Item titles, notes, or quotes in payload **broke attribute parsing** → handlers never ran (ring, date, status, title save). Package sub-tab active state also failed when `package.id` types differed (string vs number).

## Fix (production paths)

| Area | Change |
|------|--------|
| Checklist row | Handlers pass **item id only**; `_legalFindItemInOverview` + `_legalParseItemArg` resolve payload |
| Status ring / overflow | `openEditLegalItemById`; ring click without inline JSON |
| Package subtabs | `_legalPackageIdEq` + normalized `_legalActivePackageId` |
| Inline save | `_legalUpdateLocalItem` uses numeric id compare; status select updates row chrome without full reload |
| Wave H | `renderLegalChecklistStageInlineAdd` + Enter POST + DOM insert (no full tree reload) |
| IME | `_legalImeBlocksEnter` on checklist title Enter + payment row Enter |
| Payment new row | Allow create with **amount only** (no description) on empty row |
| Legacy table row | Same id-only handlers (dead UI path, kept consistent) |
| CSS | `.legal-checklist-inline-add` in `index.html` |

**Forbidden (unchanged):** `src/finance.ts`, `computeBookedRevenue`, `src/index.tsx` business logic.
