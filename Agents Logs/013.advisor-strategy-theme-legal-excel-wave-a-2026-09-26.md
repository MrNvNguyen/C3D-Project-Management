## Challenged assumption

**Team / plan / 012:** “Wave A is `shouldSync ∈ {processing,partial,paid}` + tests + dictionary; `POST /api/legal/resync-revenues-all` already exists so just run it; KPI `SUM` of revenues `pending` **tự** includes Đang xử lý and excludes Chờ thanh toán; A∥B can share a working tree; Wave C can ship as one WAVE_CARD; C/F sharing can wait.”

**Counter:**

1. **Resync as written cannot close the cut.** C5: rejected (and processing) are outside the SELECT. After `shouldSync` flips, a leftover `rejected` + `revenue_id` **stays booked** until a human finds it. Wave A **must** expand both resync queries to every row that can still have a link: `status IN ('processing','partial','paid','pending','rejected') OR revenue_id IS NOT NULL`. Pass `request_date` into `syncPaymentToRevenue`. Update the “gồm pending” comments. A runbook is a Wave A **deliverable**, not Wave G polish.
2. **“KPI tự” is a hypothesis, not a close.** Period booked that JOIN `payment_status = 'pending'` (C3) will count **processing** only after those rows exist **and** chờ-thanh-toán rows are gone. If resync skips rejected or leaves `revenue_date` null on processing, FY filters swallow the new booked. Wave A does **not** rewrite dashboard/analytics SQL. Q2 must catch leftover booked on a pending phiếu. If a route still folds `payment_requests.status = 'pending'` **into booked** (not cash-sense `pending_revenue`), that is a **new lever** after report-up — not silent scope in A.
3. **`request_date` is missing on the sync contract** (C4). Implementing only `shouldSync` leaves processing with `paid_date \|\| null` → often `null` → same year-filter drop the plan called out. Extending the payload on POST/PUT/resync is **in** the Wave A lever.
4. **A∥B is not one dispatch.** B must not touch `finance.ts`, TU-DIEN, resync, or `savePayment` toast. One lead-dev, one lever.
5. **Wave C is four levers.** Strategy locks one-sub-lever-per-dispatch **now** (see box). C/F sharing is not “undecided”: C1 **creates** the checklist row renderer; F **consumes** it; a second `exec_legal_stageTable` fork is a bar break.
